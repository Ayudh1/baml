title: (Experimental) Workflows
---

A [new experimental feature](https://www.boundaryml.com/blog/baml-workflows) allows
multiple LLM functions to be combined into a single high-level workflow. Workflows in
BAML, like LLM calls, are simply functions. They have parameters and return types,
and they can be compiled into functions in your host language to be called directly
from Python/TypeScript/Go etc.

## BAML Workflows

<Warning>
  This feature is experimental. The syntax and API are subejct to change,
  compiler errors may be less useful than those in the rest of the language,
  and the runtime behavior may not be correct. This feature is a technical
  preview intended to generate feedback for future refinement, and is not
  yet suitable for use in production apps.
</Warning>

Workflows differ from LLM functions in their function bodies, which look more similar
to the bodies of functions in general-purpose programming languages. For example, this
workflow takes a poem topic and returns two separate poems on the topic, one generated
by GPT4 and the other generated by Claude.

Example

```baml BAML
// A normal BAML class.
class Poems {
    openai string
    claude string
}

// A Workflow, which can call other LLM functions or Workflows and
// compose their results.
fn TwoPoems(topic: string) -> Poems {
    let poem_length = 10;
    Poems {
        openai: CreateGPTPoem(topic, poem_length),
        claude: CreateClaudePoem(topic, poem_length)
    }
}

// The normal BAML functions we have always been able to write.
function CreateGPTPoem(subject: string, length: int) -> string {
  client GPT4o
  prompt #"
    Please write a {{ length }} line poem about the beauty of {{ subject }}.
  "#
}

// The normal BAML functions we have always been able to write.
function CreateClaudePoem(subject: string, length: int) -> string {
  client GPT4o
  prompt #"
    Please write a {{ length }} line poem about the beauty of {{ subject }}.
  "#
}

client<llm> GPT4o {
  provider openai
  retry_policy CustomRetry
  options {
    model gpt-4o
    api_key env.OPENAI_API_KEY
  }
} 

client<llm> Claude {
  provider anthropic
  options {
    model claude-3-haiku-20240307
    api_key env.ANTHROPIC_API_KEY
    max_tokens 1000

  }
}
```
